## Runtime topology (non-obvious)

Four fixed ports, all loopback-only (zero `0.0.0.0` matches in `main.rs`): **4096** OpenCode serve, **4097** WS-4097 UI bridge, **1420** Vite dev, **4197** E2E stub control. CSP pins the browser (`connect-src 'self' ws://127.0.0.1:4097` in `tauri.conf.json`); the hello guard pins `servePort === 4096`.
Cold launch: `main.rs` writes `~/.opencode-voice-runtime/ipc.token` in `setup()` **before the webview loads**, spawns serve (if 4096 cold), then `node sidecar/dist/cli.js serve`; both children go into a `KILL_ON_JOB_CLOSE` Job Object. A daemon that never opens 4097 is killed, not left running; both child streams are captured to append-only logs (a swallowed `File::create` error once degraded to `Stdio::null()` and left zero-byte logs across spawns).
The WS bearer travels as an **extra subprotocol token** (`[voice-ui.v1, <token>]`) because browsers cannot set upgrade headers. Shell reads the token via the `ipc_token` Tauri command — it is never baked into the bundle. The server accepts `Authorization: Bearer` (timing-safe compare) **or** the subprotocol token (`ui-server.ts:306`), enforced pre-upgrade (`ui-server.ts:355`) before any frame is parsed. Never move the token to the query string: query lands in logs (RFC 6455 §1.9 workaround rationale).
Runtime state lives in `~/.opencode-voice-runtime/` (or `VOICE_RUNTIME_DIR` override): `ipc.token`, `serve.pass`, `machine.key`, `daemon.owner`, `supervisor.log`, `daemon.log` + `daemon-stdout.log`, `opencode.log` + `opencode-stdout.log`, and `voice-runtime.jsonl` (telemetry, written by the daemon). Child logs are **append-only** — a restart must not erase the previous failure.

Two IPC planes, do not confuse them. **Plane A — Tauri invoke** (shell → supervisor, 4 registered commands): `ipc_token` (reads the token file, trims, fail-closed), `ensure_all_services` (returns bring-up status; `BRINGUP_INFLIGHT` atomic guard; errors as `Ok(failed)` not `Err`), `shutdown_all_services` (registered but **uninvoked from the shell — known defect A.1**, teardown today is exit-driven only), `restrict_vault_file` (re-applies the owner-only DACL to `keyring.dat`; **invoked after every successful `saveApiKeys` — fixed A.2**). Webview capability surface is window/webview only — no fs/shell/http/process plugin reaches the renderer. **Plane B — WS-4097** (shell ↔ daemon, `ws://127.0.0.1:4097/v1/ui`): subprotocol `voice-ui.v1`, `contractVersion '3.1.0'` on all three shell surfaces (`App.tsx:113`; mismatch → `refused`, socket closed), additive zod frames (`hello` `protocol.ts:386`, `event` `protocol.ts:403`, `inventory` `protocol.ts:485`, `agents` `protocol.ts:506`, `notice` `protocol.ts:520`, `voice` `protocol.ts:535`, `context` `protocol.ts:547`, `ack` built inline `protocol.ts:470` without schema parse, `error` as inline literals). Inbound commands validate under strict `UiCommandSchema` (`protocol.ts:425`) with a bounded `ses_` regex.

Daemon identity (who holds 4097) is the `daemon.owner` marker file (`{v, pid, owner_key}`, version 1, 1500 ms settle): cold → spawn, ours → adopt, foreign → refuse-to-adopt-or-double-spawn. Identity outranks liveness (owner key checked before pid), pid 0 is explicitly foreign (`tasklist` reports pid 0 alive). The shell pre-creates the marker EMPTY only if absent; **the daemon must overwrite it in place — a rename would reset the security descriptor**. The old port-open-alone shortcut once declared "daemon already on 4097" for any squatter; the marker + identity check is the fix.

"Nemotron" survives only as the coordinator *role name* in the handoff envelope per the mission-handoff skill contract (`coordinator.ts:168`), not as a model slug — the previous Nemotron default was replaced by Inkling after a measured 5/5 valid-DAG probe.

**Three non-obvious requirements — every one was found by a live call, not by reading docs:**

1. **`User-Agent: opencode/1.0 (Voxaura)` is mandatory** (`OPENROUTER_USER_AGENT`, `src/voice/brain.ts`). Inkling answers **HTTP 403 "only available on agentic harnesses"** without an agentic UA. The allowlist is an `opencode/<version>` prefix (any version, suffixes OK); `claude-cli/`, `codex-cli/`, `cursor/` also pass. Bare `voxaura/`, `aider/`, `continue/` and browser UAs all 403. Node's default fetch sends no such UA, so **without this header every plan/narration call fails 403.** The constant is `brain.ts:23`, with the full measured allowlist in the comment above it.
2. **`reasoning: {effort:'none'}` is required for inkling.** Without it the model spends the token budget reasoning and returns `finish=length` with `content: null` — measured 0/5 narration before the fix, 5/5 after. Applied at intake (`coordinator.ts:215`, 200 tokens, temp 0.2, 10 s), narrator (`daemon.ts:369` wrapper, temp 0.8, 120 tokens, 12 s), and optimizer.
3. **The `json_schema` is load-bearing, not decorative.** Inkling prompt-only answers with raw tool-call syntax (`<|message_model|>shell<|content_invoke_tool_json|>…`) — 0/5. With strict schema: 5/5. Never relax a `response_format` to "help" a model; that reintroduces audio garbage. Narrator schema is `narrator.ts:55`; plan schema is `coordinator.ts:99` (25 s ceiling, `coordinator.ts:257`).

Measured free-tier latency (same day, same key): intake p50 **901 ms** · inkling plan p50 **1,950 ms** / max 3,987 · narration p50 **2,615 ms** / max 5,463 · STT 726 ms · TTS 3,196+1,267 ms. Free tiers are slow and lossy — re-measure, don't assume. In-tree measured comments agree: intake 1.2–1.9 s over 3 runs, plan p50 1950/max 3987 within the 25 s ceiling, narrator timeout raised 8 s → 12 s on three ~5 s measurements. Brain budget is 2.0 s golden / 5.0 s ceiling (`brain.ts:8`); STT timeout 15 s (`stt.ts:135`); Fish timeout 20 s (`tts.ts:441`).

## Vault — the single credential source

`vault/keyring.dat` (AES-256-GCM, `machine.key` in `~/.opencode-voice-runtime/`) is gitignored. Keys enter only via the API-keys window → `saveApiKeys` (the router validates all-3-present at `command-router.ts:199`-adjacent logic and delegates to the encrypted merge path).
Path resolution differs by launch: repo runs use the repo `vault/`; an **installed** build resolves to `%LOCALAPPDATA%\Voxaura\vault` (created + seeded on first run). A keyless daemon keeps the control plane up, drops audio, and emits a `voice-disabled-no-keys` notice — voice stays dead until keys are saved (which now rebuilds the pipeline live via `rebuildVoice`, `daemon.ts:912`).
Never print/log/commit key material; `doctor` reports counts only. To rotate a key by hand, call `writeKeyPools` from a script (the same encrypted merge path `saveApiKeys` uses) and **verify by SHA-256 fingerprint only** — never echo the value. A key that is *present but invalid* looks identical to a healthy one until the first utterance (L17 is open): a 401/403 advances the key and surfaces nothing. When STT/TTS/brain suddenly fails, check key validity before anything else.

Cipher (Node side): `machineKey()` prefers `VOXAURA_MACHINE_KEY` (hex → 32 B; wrong length throws `VAULT_CORRUPT` naming the real problem); fallback reads/creates `machine.key` with warn-once — the fallback is NOT equivalent and says so. `appKey()` is `scryptSync(machineKey, 'opencode-voice-runtime:vault:v1', 32)`; pools are AES-256-GCM + SHA-256 checksum (mismatch and decrypt failure both `VAULT_CORRUPT`). `FileVault.save` writes temp + rename — the rename REPLACES the file, which is why the startup DACL is silently undone by the first save and `restrict_vault_file` must re-apply it (see A.2). At baseline the Rust supervisor creates all vault secrets (`machine.key` as 32 raw bytes, hex only for the env handoff) with `restrict_to_owner` on create AND adopt, failing closed (delete + Err) on wrong length or DACL failure — because `set_permissions(0o600)` on Windows changes no ACL and `icacls /grant` cannot name the owner SID (`SetNamedSecurityInfoW` with NULL oldacl preserves it by construction; unreachable from Node without a native addon, hence the move to Rust).
Keyring discipline: `ROTATION_LIMIT` 10 reqs/key (`keyring.ts:9`); `acquire()` (`keyring.ts:75`) hands out per-call copies from cached pool material (`keyring.ts:61`); `release(key, ok, status)` (`keyring.ts:89`) advances **only** on 429/401/403; `destroy()` (`keyring.ts:115`) zeroes the cache on the `cli live` shutdown path (`cli.ts:130`).

Post-auth only: `handleUpgrade` enforces the bearer at `ui-server.ts:355` before any frame is parsed. (Note: the `protocol.ts:22` comment still says "a single frame may never exceed this" — stale wording over a per-message enforcement; see A.13-class drift.)
- **Vault DACL is Rust-owned since the hardening commit.** `restrict_to_owner` (`main.rs:653`) covers `ipc.token`, `serve.pass`, `owner.key`, `daemon.owner`, `machine.key` (create AND adopt) and `keyring.dat` (at vault-dir resolve + the `restrict_vault_file` command). ## Gotchas that cost real time

- **Pipelines in this shell lie about exit codes.** `npm run x 2>&1 | Select-Object ...` returns 1 even on success. Check `$LASTEXITCODE` *unpiped*, or redirect to a log file and read it.
- Background long builds: use `background: true`, then wait for the completion notification — do not poll.
- `git commit -F <file>` takes a **file path**, not a message; `-m` takes the message. Passing a multi-line string to `-F` makes git read it as a filename and fail. Commit messages are PowerShell-parsed: **non-ASCII quotes (`“”`) or embedded Arabic break `git commit -m`** — write the message to a temp file and use `-F`.
- **A commit message written by PowerShell 5.1 carries a UTF-8 BOM, and it silently breaks Conventional Commits.** `Out-File -Encoding utf8` and `Set-Content -Encoding utf8` both emit U+FEFF first; `git commit -F` copies it verbatim into the message. The type then parses as `﻿fix`, not `fix`, so `^(feat|fix|docs|…)` matches nothing and `conventional-changelog`/semantic-release skip the commit **without an error**. Measured on this repo: **13 of 299** commits, the most recent 13 before `3ce0f7a` — including `1f2e51e fix(security): redact provider errors at the notice sink`. `git log` renders it as a stray `﻿` before the type, which reads like a terminal artifact and is not one. **Write commit-message files with the file-write tool, or `-Encoding utf8NoBOM` on PS 7 / `[IO.File]::WriteAllText`, and check with `node -e` for `charCodeAt(0) === 0xFEFF`.** History is deliberately **not** rewritten: all 13 are on `origin/main` and their SHAs are cited in this file and in commit messages, so a fix would cost more than it buys. New commits must be clean. Verification pitfall: `git log | node -e` REPORTS a phantom BOM from PowerShell's own pipe encoding — capture to a variable (`$m = git log -1 --format=%B`), never verify via pipes.
- The GitHub remote is **private** (`3mar-baha/Vantrilex-OpenCode-Assistant`), default branch `main`; there is no `master`. `git log origin/main..main` shows unpushed work — the installed app tracks the last *release*, not local HEAD.
- **Free OpenRouter models are lossy, not just 429.** Inkling is a reasoning model: without `effort:'none'` it returns `content: null`. Nemotron measured 3/12 success at p50 4,831 ms. A malformed single field used to void an entire reply — the narrator and intake both coerce/validate now, so a schema deviation costs a degraded line, not silence. Always measure before blaming your own code.
- **STT pins `language: 'ar'`.** Feeding it English audio yields Arabic gibberish *by design* — that is not a Whisper bug and not a key problem. To test Arabic STT you need real (or TTS-synthesised) Arabic audio.
- **A binary WS frame over `MAX_AUDIO_BYTES` (64 KiB) is rejected** with an `error` frame and never reaches the pipeline — silently, if you aren't collecting `error` frames. The window is 160,000 bytes, so send it in ≤32 KiB chunks like the renderer does.
- The Windows **taskbar icon is cached** by Explorer keyed on the exe path. Replacing icons does nothing until you stop `explorer.exe`, delete `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db`, and restart it (`ie4uinit.exe -show` is not sufficient).
- Rust resolves `resource_dir` with a `\\?\` prefix; Node's resolver rejects it — the supervisor strips it before handing paths to the child.
- A helper that both **prints and returns** in PowerShell captures its diagnostic *strings* as the return value. That silently produced a gate reporting "30/30 ORPHAN" from a number it never measured. Separate `Write-Host` from `return`.
- **Verify a guard test by breaking the guard.** Disabling the fix and confirming the test fails is the only way to know it isn't vacuous. Several tests here were vacuous until checked. Two were worse — they **pinned bugs as features**: `capture-permission.test.ts` asserts an idempotency guard that makes every mic-recovery path a silent no-op, and a `ws.test.ts` case *named* "resumes seq" asserted that **no** resume param was sent. A test whose name contradicts its assertion is a smell worth reading for.
- **A test can be vacuous because your injection silently no-opped.** Twice now, a break-the-guard passed only because the anchor string didn't exist in the file. Always print a confirmation line that the injection landed before trusting a green break.
- **`scripts/provision-sidecar.mjs` writes its OWN manifest** (and runs its own `npm install`), so **removing a dependency from root `package.json` does not remove it from the installer**. That is how `pino` and `eventsource` kept shipping after being deleted at the root. Change both places, then verify eradication rather than assuming it: `node -e` over the lock, and `npm ls` for extraneous.
- **`ui.notice()` is the redaction SINK for provider errors — that part is exact. "The only channel a user can see" was too wide and is corrected here.** `daemon.ts` interpolates raw provider `err.message` into notices (`daemon.ts:669` STT, `:823` brain, `daemon.ts:894` TTS — the `:894` branch is the credit interceptor); redaction lives in `UiServer.notice()` (`ui-server.ts:229`), not at those call sites, so a new call site cannot leak. Do not "helpfully" move redaction outward to the callers. **But three other frame types also reach the client and none of them redacts:** `voice()` (`ui-server.ts:233`, carrying the user's own transcript), `ack` (`ui-server.ts:505`), and `event`/`inventory`/`agents` (`ui-server.ts:161`, `ui-server.ts:177`, `ui-server.ts:189`). None can carry a secret today — `ack.detail` values are locally generated literals (see below) and the inventory frames are serialised local OpenCode state — so there is **no live leak**. The property nevertheless rests on that coincidence rather than on the sink: the next `onCommand` implementation that returns a raw provider message would leak silently. `encodeTextFrame` is imported only inside `ui-server.ts`, so the frame surface IS fully enumerable, which is what makes this auditable.
- **`ack.detail` is an OPEN string, not a closed union — corrected 2026-09-29.** An earlier revision of this file called it a closed `ErrorCode` union; that was wrong. The type is `CommandOutcome{ ok: boolean; detail?: string }` (`command-router.ts:12`, field at `command-router.ts:14`). The invariant "locally generated, never provider text" holds **by convention, not by type**: `dispatch` (`command-router.ts:151`) returns literals (`'confirmation-required'` at `command-router.ts:270`, `'persona-set'` at `command-router.ts:199`, session-id/context strings built from local state) and the catch maps `OrchestratorError → err.code` (`command-router.ts:274`) else `'internal'`. But `dispatchCommand`'s catch (`ui-server.ts:503`) forwards raw `err.message` into `ack.detail` — reachable only if `onCommand` throws, which the router never does today. One throwing `onCommand` implementation is all it takes; redact `ack.detail` at the sink (Triad B.5).
- **The shell needs `?lastSeq=` on the FIRST connect, not just reconnects.** `lastSeq` is initialised to `-1` as a "never connected" sentinel; keying the query param off `>= 0` omits it on connect #1, the server's `lastSeqOf` then returns `NaN`, and `ui-server.ts` skips the entire replay block. Measured cost: a cold launch sat with an empty session list and agent selector for 25+ s. Floor the value with `Math.max(0, …)` (`ws.ts:281`) and keep the sentinel.
- **`normalizeArabic` must not be widened by a dash range.** The class was `U+064B-U+0672`, which swallows the Arabic-Indic digits `U+0660-U+0669`; `المنفذ ٤٠٩٦ مشغول` lost its port number before it was ever scored. The class is now explicit with the gaps as the comment (`normalize.ts:23`). Also: minisearch and most JS search libs ship **no** Arabic orthographic handling at all, so a normalizer must be passed in at both index and query time or Arabic recall silently goes to zero.
