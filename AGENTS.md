# AGENTS.md — Voxaura (opencode-voice-runtime)

Windows-first Tauri v2 desktop companion + Node daemon that drives OpenCode v2 (`opencode serve`) via voice.
**Trust code, not prose.** `docs/PROJECT_MASTER_DOSSIER.md` (baseline `6be0363`, 1050 lines, code-first, zero-trust) is the audit of record; `docs/01–28` are a frozen, partly-wrong spec set. ## Runtime topology (non-obvious)

Four fixed ports, all loopback-only (zero `0.0.0.0` matches in `main.rs`): **4096** OpenCode serve, **4097** WS-4097 UI bridge, **1420** Vite dev, **4197** E2E stub control. CSP pins the browser (`connect-src 'self' ws://127.0.0.1:4097` in `tauri.conf.json`); the hello guard pins `servePort === 4096`.
Cold launch: `main.rs` writes `~/.opencode-voice-runtime/ipc.token` in `setup()` **before the webview loads**, spawns serve (if 4096 cold), then `node sidecar/dist/cli.js serve`; both children go into a `KILL_ON_JOB_CLOSE` Job Object. A daemon that never opens 4097 is killed, not left running; both child streams are captured to append-only logs (a swallowed `File::create` error once degraded to `Stdio::null()` and left zero-byte logs across spawns).
The WS bearer travels as an **extra subprotocol token** (`[voice-ui.v1, <token>]`) because browsers cannot set upgrade headers. Shell reads the token via the `ipc_token` Tauri command — it is never baked into the bundle. The server accepts `Authorization: Bearer` (timing-safe compare) **or** the subprotocol token (`ui-server.ts:464`), enforced pre-upgrade (`ui-server.ts:482`) before any frame is parsed. Never move the token to the query string: query lands in logs (RFC 6455 §1.9 workaround rationale).
Runtime state lives in `~/.opencode-voice-runtime/` (or `VOICE_RUNTIME_DIR` override): `ipc.token`, `serve.pass`, `machine.key`, `daemon.owner`, `supervisor.log`, `daemon.log` + `daemon-stdout.log`, `opencode.log` + `opencode-stdout.log`, and `voice-runtime.jsonl` (telemetry, written by the daemon). Child logs are **append-only** — a restart must not erase the previous failure.

Two IPC planes, do not confuse them. **Plane A — Tauri invoke** (shell → supervisor, 3 registered commands): `ipc_token` (reads the token file, trims, fail-closed), `ensure_all_services` (returns bring-up status; `BRINGUP_INFLIGHT` atomic guard; errors as `Ok(failed)` not `Err`), `restrict_vault_file` (re-applies the owner-only DACL to `keyring.dat`; **invoked after every successful `saveApiKeys` — fixed A.2**). The fourth command, `shutdown_all_services`, was **deleted** (A.1): it had zero shell call sites, and `Supervisor::reap()` stays because the `ExitRequested`/`Exit` path in `main()` is its real caller. Webview capability surface is window/webview only — no fs/shell/http/process plugin reaches the renderer. **Plane B — WS-4097** (shell ↔ daemon, `ws://127.0.0.1:4097/v1/ui`): subprotocol `voice-ui.v1`, `contractVersion '3.1.0'` on all three shell surfaces (`App.tsx:251`; mismatch → `refused`, socket closed), additive zod frames (`hello` `protocol.ts:413`, `event` `protocol.ts:448`, `inventory` `protocol.ts:571`, `agents` `protocol.ts:617`, `notice` `protocol.ts:631`, `voice` `protocol.ts:646`, `context` `protocol.ts:657`, `ack` `protocol.ts:546` — **it has a schema**, contradicting this line until 2026-09-30, `error` as inline literals). Inbound commands validate under strict `UiCommandSchema` (`protocol.ts:469`) with a bounded `ses_` regex.

Daemon identity (who holds 4097) is the `daemon.owner` marker file (`{v, pid, owner_key}`, version 1, 1500 ms settle): cold → spawn, ours → adopt, foreign → refuse-to-adopt-or-double-spawn. Identity outranks liveness (owner key checked before pid), pid 0 is explicitly foreign (`tasklist` reports pid 0 alive). The shell pre-creates the marker EMPTY only if absent; **the daemon must overwrite it in place — a rename would reset the security descriptor**. The old port-open-alone shortcut once declared "daemon already on 4097" for any squatter; the marker + identity check is the fix.

## Models — all free tier, and three things that break silently

Routing table (every slug is `:free`; the 100%-free constraint is a product decision, not an accident):

| Role | Constant | Slug |
|---|---|---|
| Conversational intake | `INTAKE_MODEL` (`src/orchestrator/coordinator.ts`) | `thinkingmachines/inkling:free` (re-picked by measurement 2026-10-01 — see the intake quota note below) |
| Coordinator / planner | `COORDINATOR_MODEL` (same file) | `thinkingmachines/inkling:free` |
| Narrator (spoken confirmations) | `NARRATOR_MODEL` (`src/orchestrator/narrator.ts`) | `thinkingmachines/inkling:free` |
| Brain / `cli live` | `BRAIN_OPENROUTER_MODEL` (`src/voice/brain.ts`) | `thinkingmachines/inkling:free` |

Model constants live at `coordinator.ts:116` (intake), `coordinator.ts:117` (planner), `narrator.ts:52` (narrator), `brain.ts:191` (brain), and TTS is Fish-only: `TTS_MODEL = 's2.1-pro-free'` (`tts.ts:31`). "Nemotron" survives only as the coordinator *role name* in the handoff envelope per the mission-handoff skill contract — the previous Nemotron default was replaced by Inkling after a measured 5/5 valid-DAG probe. Handoff envelope builder is `coordinator.ts:417`.

**INTAKE IS KEY-SCOPED ON THE FREE TIER, NOT MODEL-SCOPED — measured 2026-10-01.** The `:free` flag means zero-cost, not zero-quota. `GET /api/v1/key` returns `is_free_tier: true`, `total_credits: 0`, and `free_model_daily_requests: { used, limit: 50, remaining }` — **one 50-requests-per-day pool per key, shared by every `:free` model.** The 429 body says so outright: *"Rate limit exceeded: free-models-per-day. Add 10 credits to unlock 1000 free model requests per day"*, with `X-RateLimit-Remaining: 0` and `X-RateLimit-Reset` naming the UTC midnight boundary. A burst probe made the scope unambiguous in one run: the primary answered 200 ×8 then 429 ×4 mid-burst, and the model probed immediately after returned 429 ×12. **So "swap to a different `:free` model" is not a fix for a quota outage.** A sweep of all 16 free models, one real call each at `remaining: 0`, found only `thinkingmachines/inkling:free` and `thinkingmachines/inkling-small:free` answering at all; the other thirteen returned 429 and `liquid/lfm-2.5-2.6b:free` returned 400 (*"Reasoning is mandatory for this endpoint and cannot be disabled"*), with `used` flat across the sweep. `inkling-small` is structurally reliable (8/8 valid) but semantically broken: every line confabulates a model swap and a near-full context that was never supplied, and one `task_en` echoed the system prompt back as the dispatch instruction.

`inkling` was then measured for intake on the production option set (`{effort:'none'}`, 200 tokens, temp 0.2, 10 s) over 12 real Arabic utterances: **12/12 schema-valid, p50 743 ms, 0/12 CJK, 0/12 other non-Arabic script**, and `completion_tokens_details.reasoning_tokens = 0` on every call — a controlled same-session comparison, because with the `reasoning` field omitted the same model reports 338 reasoning tokens, so `effort:'none'` is demonstrably honoured rather than assumed. The retired `dots-3` measured 8/8 valid but polluted **3 of 8** lines the user would *hear*: `فهمت، سأحذف太平洋 dist فورًا و أ})` (Han), `بIni شغل البناء` (Latin glued mid-word), and one `reply_ar` returned entirely in English. It was disqualified on that, not on latency. `nvidia/nemotron-3-super-120b-a12b:free` measured best of all on quality before the pool died (8/8 valid, p50 331 ms, max 412 ms, 0/8 CJK) and **is the pick to revisit once the daily budget is funded or resets** — it is 429 today, and shipping the best model that cannot run is not unblocking a stage.

**Three known costs of the inkling re-pick, all measured, none hidden:**

- **The intake failover is now self-referential.** `intake()` iterates `[intakeModel, fallbackModel]` and both are `thinkingmachines/inkling:free`, so it buys no diversity — a live `cli reason` run shows `model calls 2` with both legs on the same slug.
- **The failover path is independently dead (0/6).** It passes `undefined` options, so `brain.ts` defaults apply: `maxTokens 300`, **no `effort:'none'`**, and the `BRAIN_CEILING_MS` 5 s ceiling instead of intake's 10 s. Six consecutive calls all aborted at 5 s. This was observed live as `intake-invalid` — HTTP 200 with `extractJson()` returning `null`. Any reasoning model on that path is a 5-second race it cannot win. **The fix is to give intake a distinct fallback and pass it the same decoding controls as the primary**, which needs `COORDINATOR_MODEL` (or a new intake-fallback constant) and the call site in `coordinator.ts` — both outside the 2026-10-01 change's write set.
- **`turn.ts`'s stage classifier now discriminates on SHAPE, not slug — FIXED, and the comment says why.** The old classifier compared `model === INTAKE_MODEL` / `model === COORDINATOR_MODEL` and tested intake first, so a collision put every plan call in the `intake` arm and `approve.plan` was permanently `null`. It reads `schemaKind` off `options.responseFormat` (`turn.ts:221`) and branches on that (`turn.ts:233`): the gate's addressee schema, any other strict schema (only `plan()` sends one) as `plan` (`turn.ts:242`), then a 3 s budget as the re-ask, then `options === undefined` as the failover leg, and the remaining shape as primary intake. The plan recovery is `lastPlanOf` (`turn.ts:385`), which filters on `stage !== 'plan'` (`turn.ts:388`). Two `turn.test.ts` cases drive the collided AND distinct configurations, so the guard does not depend on the current pairing.
- **Latency tail:** 1 of 13 calls exceeded the 10 s ceiling on the same utterance that completed in 796 ms later. A reliability cost, not a correctness one — the turn still fails closed.

**Three non-obvious requirements — every one was found by a live call, not by reading docs:**

1. **`User-Agent: opencode/1.0 (Voxaura)` is mandatory** (`OPENROUTER_USER_AGENT`, `src/voice/brain.ts`). Inkling answers **HTTP 403 "only available on agentic harnesses"** without an agentic UA. The allowlist is an `opencode/<version>` prefix (any version, suffixes OK); `claude-cli/`, `codex-cli/`, `cursor/` also pass. Bare `voxaura/`, `aider/`, `continue/` and browser UAs all 403. ## Vault — the single credential source

`vault/keyring.dat` (AES-256-GCM, `machine.key` in `~/.opencode-voice-runtime/`) is gitignored. Keys enter only via the API-keys window → `saveApiKeys` (the router validates all-3-present at `command-router.ts:627`-adjacent logic and delegates to the encrypted merge path).

A keyless daemon keeps the control plane up, drops audio, and emits a `voice-disabled-no-keys` notice — voice stays dead until keys are saved (which now rebuilds the pipeline live via `rebuildVoice`, `daemon.ts:1579`).

A key that is *present but invalid* looks identical to a healthy one until the first utterance (L17 is open): a 401/403 advances the key and surfaces nothing. - **Vault DACL is Rust-owned since the hardening commit.** `restrict_to_owner` (`main.rs:700`) covers `ipc.token`, `serve.pass`, `owner.key`, `daemon.owner`, `machine.key` (create AND adopt) and `keyring.dat` (at vault-dir resolve + the `restrict_vault_file` command). ## Gotchas that cost real time

- **Pipelines in this shell lie about exit codes.** `npm run x 2>&1 | Select-Object ...` returns 1 even on success. Check `$LASTEXITCODE` *unpiped*, or redirect to a log file and read it.
- Background long builds: use `background: true`, then wait for the completion notification — do not poll.
- `git commit -F <file>` takes a **file path**, not a message; `-m` takes the message. Passing a multi-line string to `-F` makes git read it as a filename and fail. Commit messages are PowerShell-parsed: **non-ASCII quotes (`“”`) or embedded Arabic break `git commit -m`** — write the message to a temp file and use `-F`.
- **A commit message written by PowerShell 5.1 carries a UTF-8 BOM, and it silently breaks Conventional Commits.** `Out-File -Encoding utf8` and `Set-Content -Encoding utf8` both emit U+FEFF first; `git commit -F` copies it verbatim into the message. The type then parses as `﻿fix`, not `fix`, so `^(feat|fix|docs|…)` matches nothing and `conventional-changelog`/semantic-release skip the commit **without an error**. Measured on this repo: **13 of 299** commits, the most recent 13 before `3ce0f7a` — including `1f2e51e fix(security): redact provider errors at the notice sink`. `git log` renders it as a stray `﻿` before the type, which reads like a terminal artifact and is not one. **Write commit-message files with the file-write tool, or `-Encoding utf8NoBOM` on PS 7 / `[IO.File]::WriteAllText`, and check with `node -e` for `charCodeAt(0) === 0xFEFF`.** History is deliberately **not** rewritten: all 13 are on `origin/main` and their SHAs are cited in this file and in commit messages, so a fix would cost more than it buys. New commits must be clean. Verification pitfall: `git log | node -e` REPORTS a phantom BOM from PowerShell's own pipe encoding — capture to a variable (`$m = git log -1 --format=%B`), never verify via pipes.
- The GitHub remote is **private** (`3mar-baha/Vantrilex-OpenCode-Assistant`), default branch `main`; there is no `master`. `git log origin/main..main` shows unpushed work — the installed app tracks the last *release*, not local HEAD.
- **Free OpenRouter models are lossy, not just 429.** Inkling is a reasoning model: without `effort:'none'` it returns `content: null`. Nemotron measured 3/12 success at p50 4,831 ms. A malformed single field used to void an entire reply — the narrator and intake both coerce/validate now, so a schema deviation costs a degraded line, not silence. Always measure before blaming your own code.
- **STT pins `language: 'ar'`.** Feeding it English audio yields Arabic gibberish *by design* — that is not a Whisper bug and not a key problem. To test Arabic STT you need real (or TTS-synthesised) Arabic audio.
- **A binary WS frame over `MAX_AUDIO_BYTES` (64 KiB) is rejected** with an `error` frame and never reaches the pipeline — silently, if you aren't collecting `error` frames. The window is 160,000 bytes, so send it in ≤32 KiB chunks like the renderer does.
- The Windows **taskbar icon is cached** by Explorer keyed on the exe path. Replacing icons does nothing until you stop `explorer.exe`, delete `%LOCALAPPDATA%\Microsoft\Windows\Explorer\iconcache_*.db`, and restart it (`ie4uinit.exe -show` is not sufficient).
- Rust resolves `resource_dir` with a `\\?\` prefix; Node's resolver rejects it — the supervisor strips it before handing paths to the child.
- A helper that both **prints and returns** in PowerShell captures its diagnostic *strings* as the return value. That silently produced a gate reporting "30/30 ORPHAN" from a number it never measured. Separate `Write-Host` from `return`.
- **Verify a guard test by breaking the guard.** Disabling the fix and confirming the test fails is the only way to know it isn't vacuous. Several tests here were vacuous until checked. Two were worse — they **pinned bugs as features**: `capture-permission.test.ts` asserts an idempotency guard that makes every mic-recovery path a silent no-op, and a `ws.test.ts` case *named* "resumes seq" asserted that **no** resume param was sent. A test whose name contradicts its assertion is a smell worth reading for.
- **A test can be vacuous because your injection silently no-opped.** Twice now, a break-the-guard passed only because the anchor string didn't exist in the file. Always print a confirmation line that the injection landed before trusting a green break.
- **`scripts/provision-sidecar.mjs` writes its OWN manifest** (and runs its own `npm install`), so **removing a dependency from root `package.json` does not remove it from the installer**. That is how `pino` and `eventsource` kept shipping after being deleted at the root. Change both places, then verify eradication rather than assuming it: `node -e` over the lock, and `npm ls` for extraneous.
- **`ui.notice()` is the redaction SINK for provider errors — that part is exact, and `output` has now JOINED it. "The only channel a user can see" was too wide and is corrected here.** `daemon.ts` interpolates raw provider `err.message` into notices (`daemon.ts:1199` STT, `daemon.ts:1424` brain, `daemon.ts:1548` TTS — the `daemon.ts:1532` branch is the credit interceptor); redaction lives in `UiServer.notice()` (`ui-server.ts:341`), not at those call sites, so a new call site cannot leak. Do not "helpfully" move redaction outward to the callers. **Redaction at a sink covers the free-text frames, and the set of frames is LARGER than any list in this paragraph — do not read this paragraph as the enumeration.** `voice()` (`ui-server.ts:357`, the user's own transcript) and `ack` (`ui-server.ts:732`) pass their free-text field through `redactString` *at the write point*, so a future caller cannot skip it — the same reasoning that makes `notice()` (`ui-server.ts:343`) a sink. `event`/`inventory`/`agents` (`ui-server.ts:233`, `ui-server.ts:248`, `ui-server.ts:260`) are **not** redacted; they carry no free text today (serialised local OpenCode state, plus a bounded session/persona id), so there is **no live leak** — but that half of the property still rests on coincidence rather than on the sink, and it is the honest residual. `context` (`ui-server.ts:368`, schema `protocol.ts:657`) is all-numeric. **`output` was the gap, and it was the reason this paragraph used to be wrong — it is now closed.** It carries up to 32 KiB of shell stdout (`MAX_OUTPUT_TEXT_BYTES`, `protocol.ts:751`) plus the `command` line (`UiServer.output()`, `ui-server.ts:312`, routes through `buildOutputFrame` at `ui-server.ts:316`; schema `protocol.ts:908`), and it reaches the renderer AND the retained resume window, so a leak there was both immediate and replayable. `buildOutputFrame` (`protocol.ts:997`) is the single function every `output` frame must pass through, and it runs `redactString` on both free-text fields itself (`protocol.ts:999`, `protocol.ts:1000`) — the sink, not the call site, so a future producer inherits it. **Redaction runs BEFORE the assembler, and that ordering is load-bearing, not stylistic:** `[REDACTED]` is 10 bytes, so redacting after the 32 KiB cap could GROW an already-at-cap string past `MAX_OUTPUT_TEXT_BYTES` and throw inside `OutputFrameSchema.parse` — a redaction that takes down the producer. The stated consequence is that `outputBytes` reports the byte length of the REDACTED text, not of the raw stdout, which is the safer direction to be wrong in. **The pattern list behind that sink is one table, not three prefixes.** `CREDENTIAL_FAMILIES` (`src/common/logger.ts`, declared at `logger.ts:78`) declares sixteen families — the three this build holds (`sk-or-v1-`, `sk-fish-`, `gsk_`) plus Anthropic `sk-ant-`, OpenAI `sk-proj-`, Google `AIza`, GitHub `gh[pousr]_` (all five token types), Slack `xox[abprs]-`, Stripe `[rs]k_live_`, npm, HuggingFace, SendGrid, Mailgun, AWS `AKIA|ASIA|AROA|AGPA|AIDA`, Azure `AccountKey=` and JWT — and BOTH `LIVE_PREFIXES` (`logger.ts:215`) and the compiled `REDACTION_PATTERNS` (`logger.ts:258`) are derived from it, so a family cannot be documented without being caught and a pattern cannot exist without a sample proving it fires. The old shape was a three-element `LIVE_PREFIXES` beside a hand-typed pattern list that could disagree with it, and it did: 15 synthetic shapes pushed through the real `redactString` had **12 of 15 pass through untouched**, because the list only ever named the pools this build holds. **The frame count, re-derived 2026-10-01: `protocol.ts` exports 10 frame schemas carrying a `type: z.literal(...)` discriminator** — `hello` `event` `ack` `inventory` `agents` `notice` `voice` `context` `flow` `output` — **and the wire carries an 11th, `error`, written as inline literals with no schema at all** (`ui-server.ts:689`). Re-derive rather than trust this line: `grep -c 'type: z\.literal(' src/ipc/protocol.ts`. **What the single-importer property actually buys is the ENCODE surface, not the frame surface.** `encodeTextFrame` has exactly one caller in `src/` — `ui-server.ts` — and a test asserts that count, so every outbound frame is *written* in one file and the write points are enumerable. It says nothing about how many frame types exist. An earlier revision of this line read "so the frame surface IS fully enumerable" immediately after that property and enumerated 7 frames; `hello`, `flow`, `output` and `error` were all missing, and the closed-enumeration claim is exactly the reasoning that let an unredacted `output` path sit unnoticed. **The encode surface was always enumerable. The frame surface never was.** **The trade B.5 accepts:** `voice.transcript` is the user's own speech, so a user who *dictates* a key sees it masked on their own HUD — fail-closed by choice, since that frame also reaches client-side log/bug-report paths.
- **`ack.detail` is an OPEN string, not a closed union — corrected 2026-09-29.** An earlier revision of this file called it a closed `ErrorCode` union; that was wrong. The type is `CommandOutcome{ ok: boolean; detail?: string }` (`command-router.ts:45`, field at `command-router.ts:47`). The invariant "locally generated, never provider text" holds **by convention, not by type**: `dispatch` (`command-router.ts:547`) returns literals (`'confirmation-required'` at `command-router.ts:820`, `'persona-set'` at `command-router.ts:638`, session-id/context strings built from local state) and the catch maps `OrchestratorError → err.code` (`command-router.ts:837`) else `'internal'`. But `dispatchCommand`'s catch (`ui-server.ts:721`) forwards raw `err.message` into `ack.detail` — reachable only if `onCommand` throws, which the router never does today. **Closed at the sink (B.5):** `redactString(outcome.detail)` runs at the ack write point (`ui-server.ts:732`), so the convention is now backed by the sink.
- **The shell needs `?lastSeq=` on the FIRST connect, not just reconnects.** `lastSeq` is initialised to `-1` as a "never connected" sentinel; keying the query param off `>= 0` omits it on connect #1, the server's `lastSeqOf` then returns `NaN`, and `ui-server.ts` skips the entire replay block. Measured cost: a cold launch sat with an empty session list and agent selector for 25+ s. Floor the value with `Math.max(0, …)` (`ws.ts:490`) and keep the sentinel.
- **`normalizeArabic` must not be widened by a dash range.** The class was `U+064B-U+0672`, which swallows the Arabic-Indic digits `U+0660-U+0669`; `المنفذ ٤٠٩٦ مشغول` lost its port number before it was ever scored. The class is now explicit with the gaps as the comment (`normalize.ts:23`). Also: minisearch and most JS search libs ship **no** Arabic orthographic handling at all, so a normalizer must be passed in at both index and query time or Arabic recall silently goes to zero.
